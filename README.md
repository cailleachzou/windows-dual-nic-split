# 一键双网卡分流（Windows）

一个不依赖任何第三方工具的批处理脚本：让**外网走外网接口**、**Wi-Fi 只走内网**，并把内网 NAS 的路由固定下来。

典型场景：笔记本同时插着 USB 共享网络 / 手机热点（外网），又连着公司 Wi-Fi（内网 + NAS）。默认情况下 Windows 会随机挑一个出口，导致要么没网、要么 NAS 连不上。脚本通过**接口跃点数 + 持久静态路由**把这件事钉死。

## 用法

| 操作 | 方法 |
|------|------|
| 配置分流 | **双击运行**（会自动弹 UAC 申请管理员权限） |
| 还原设置 | 命令行执行 `一键双网卡分流.bat /restore` |

脚本会：

1. 自动识别**已连接的无线网卡**（视为内网）和**另一个已连接且带网关的接口**（视为外网）
2. 外网接口跃点数设为 `5`，内网 Wi-Fi 设为 `999`
3. 添加持久静态路由：`192.168.1.0/24` → Wi-Fi 网关，`metric 1`
4. 把当前 `route print -4` 和 `netsh interface ipv4 show interfaces` 备份到脚本同目录的 `网络配置备份.txt`
5. 用 ping 验证外网、内网网关、NAS 三项连通性

还原时会删除静态路由，并把两块网卡的跃点数改回 `automatic`。

## 自定义

同事的 NAS 网段不同时，改脚本开头的三行即可：

```bat
set "NAS_NET=192.168.1.0"
set "NAS_MASK=255.255.255.0"
set "NAS_IP=192.168.1.100"
```

> `NAS_IP` 只用于最后的连通性验证，不影响路由配置；没有 NAS 可以忽略提示。

## 注意

- **文件编码必须是 GBK（cp936）+ CRLF**。用 UTF-8 保存会导致 `chcp 936` 之外的中文全部乱码，`echo` 和 `findstr` 匹配也会失效。因此在 GitHub 网页上直接查看本文件会显示乱码，这是预期行为，下载到本地运行正常。
- 需要管理员权限；脚本会自己通过 VBScript 提权，不需要手动右键。
- 无线网卡名支持中文（如 `LM_CORP`）。
- 判断依据是「已连接 + 有默认网关」，请确保内网 Wi-Fi 已经拿到 IP。

## 环境

Windows 10 / 11，仅使用系统自带的 `netsh`、`route`、`findstr`、`cscript`，无需安装任何东西。
